# Contributing

Keep the guide model-agnostic and practical. Explain which failure a change addresses, how ownership and live operations remain coherent, and how the behavior can be evaluated.

Use generic or synthetic examples. Do not submit credentials, personal data, private project names, internal paths, machine identifiers, or raw private execution logs. Preserve the distinction between policy guidance and guarantees implemented by a runtime.

When changing the diagram, update its editable sources and exported images. When changing the global prompt, regenerate the README prompt block and check that it matches the plain-text version. Add or adjust an evaluation scenario for meaningful behavior changes.

Open an issue for discussion or a pull request with the concrete change and relevant checks. Contributions are provided under the repository's MIT license.
